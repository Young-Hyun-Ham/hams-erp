# HAMS WORKS · 사내 ERP

IT 아웃소싱 기업의 직원·프리랜서 인사 정보, 출퇴근, 원격근무 상태와 월 급여·정산 초안을 관리하는 서비스입니다. 회원등록과 계정별 비밀번호 인증을 지원합니다.

## 빠른 시작

프로젝트 디렉터리에서 실행합니다. 현재 개발 서버 포트는 **3014**입니다.

```powershell
pnpm install
# 설정 파일이 없을 때만 복사하고 실제 값을 수정하세요.
Copy-Item .env.example .env.local
pnpm dev
```

접속: http://localhost:3014

기존 `.env.local`을 덮어쓰지 마세요. `.env.local`과 `.env`에 같은 키가 있으면 보통 `.env.local` 값이 우선합니다. DB 설정은 [환경 설정 상세](docs/deployment.md)를 확인하세요.

| 샘플 역할 | 이메일 | 권한 |
| --- | --- | --- |
| 관리자 | admin@hams.demo | 전체 구성원·근태·원격 상태·정산 조회, 인사·정산 수정 |
| 직원 | member@hams.demo | 본인 정보·근태·원격 상태·정산 조회, 본인 근무 기록 |
| 프리랜서 | partner@hams.demo | 직원과 동일한 개인 권한, 계약 유형은 프리랜서 |

모든 계정의 **초기 비밀번호는 `hams1234!`**입니다. 첫 로그인 후 메인 화면에 닫을 수 없는 변경 모달이 열립니다. 초기 비밀번호와 다른 10~128자 비밀번호로 변경해야 업무 데이터를 조회하거나 기능을 사용할 수 있습니다. 이후에는 변경한 비밀번호로 로그인합니다.

로그인 화면의 **회원등록** 버튼 또는 [/register](http://localhost:3014/register)에서 이름·이메일·소속·직무·계약 유형을 입력합니다. 신규 회원은 일반 구성원 권한, 월 금액 0원, 프로젝트 미배정으로 생성됩니다. 관리자가 금액·프로젝트를 수정합니다. 관리자 화면의 구성원 등록도 초기 비밀번호가 있는 로그인 계정을 생성합니다.

비밀번호는 개인별 무작위 salt와 scrypt로 해시하여 `employees.password_hash`에 저장합니다. 원문·해시는 API 조회 응답에 포함하지 않습니다. 기존 DB는 첫 API 요청에서 인증 컬럼과 초기 해시를 추가하고 해당 계정의 기존 세션을 무효화합니다. 기존 인사·근태·정산은 유지하고 이미 변경한 비밀번호는 다시 초기화하지 않습니다. [인증·전환 상세](docs/authentication.md)

## 제공 기능

| 화면 | 현재 동작 |
| --- | --- |
| 대시보드 | 권한 범위 내 구성원 수, 오늘 근무 인원, 원격 활동 인원, 당월 지급 예정액 |
| 구성원 관리 | 직원·프리랜서 등록·수정, 계약 유형 필터, 이름·소속·프로젝트·이메일 검색 |
| 출퇴근 관리 | 사무실·원격 선택 후 본인 출퇴근 기록, 한국 날짜 기준 하루 한 번 출근, 월별 조회·CSV |
| 원격근무 | 원격 출근·동의 후 업무와 기기 활동 공유, 활동 중·자리 비움·자동 판정 불가·연결 확인 필요 표시 |
| 급여·정산 | 월별 초안 생성, 수당·공제 입력, 검토 상태 관리, 개인 내역 조회 |

원격근무 테스트는 **직원 로그인 → 출퇴근 관리 → 원격 근무 선택 → 출근하기 → 원격근무 → 내 업무 상태 공유** 순서입니다. 관리자 창과 직원 창은 일반 창·시크릿 창 등 별도 쿠키 세션을 사용합니다. 이미 사무실 출근 또는 퇴근한 계정은 당일 원격 재출근할 수 없습니다. [테스트 절차](docs/testing.md)

기기 활동 자동 판정에는 Idle Detection 지원 브라우저, HTTPS(또는 신뢰 가능한 로컬 개발 환경), 사용자 권한 허용이 필요합니다. 관리자는 헤더 사용자 이름 → 원격지원설정에서 공통 자리비움 시간을 1~120분(기본 5분)으로 저장합니다. 공유 중인 브라우저는 다음 데이터 갱신 때 적용합니다. 최소화 자체는 자리비움 조건이 아니며, 설정 시간 동안 기기 입력이 없거나 화면을 잠그면 자리비움입니다. 미지원·권한 거절은 자동 판정 불가, 통신 중단 3분 초과는 연결 확인 필요입니다. 브라우저 종료·절전·탭 중단 시 지속 전송은 보장하지 않습니다.

## 데이터 저장과 배포

| 변수 | 역할 |
| --- | --- |
| `ERP_DATABASE_URL` | 원격 libSQL DB 주소. 비어 있으면 로컬 `file:data/erp.db` |
| `ERP_DATABASE_AUTH_TOKEN` | DB 연결 인증 토큰. 로그인 비밀번호와 별개 |

기존 `ERP_DEMO_PASSWORD`, `ERP_ENABLE_DEMO_LOGIN`은 더 이상 사용하지 않습니다. Vercel에서 이 값을 바꿔도 계정 비밀번호는 바뀌지 않습니다.

첫 API 요청에서 테이블과 샘플 구성원 6명을 초기화합니다. 출퇴근·원격 상태·급여 내역은 실제 요청으로 생성됩니다. 원격 DB에 연결하면 로컬 DB를 사용하지 않으며, 로컬 기록을 자동 이관하지 않습니다.

Vercel에서는 원격 DB 주소·토큰을 환경 변수에 등록하고 재배포합니다. 인증 컬럼 추가·기존 계정 전환이 있으므로 기존 DB는 배포 전 백업하세요. 로컬 `.env` 파일만 수정해서는 Vercel 환경에 반영되지 않습니다. [Vercel·Turso 운영 안내](docs/deployment.md)

현재 저장소에서는 **`data/erp.db`가 Git에 추적되고 있으며 `.gitignore`에 `/data/` 규칙이 없습니다.** 이 문서화 작업은 DB 파일과 추적 상태를 변경하지 않습니다. 해당 파일 배포는 원격 DB 연결·초기화·데이터 이관을 대신하지 않습니다.

## 기술 구성

Next.js 16.4.2 App Router, React 19.3.0, TypeScript, Tailwind CSS 4, lucide-react, `@libsql/client`를 사용합니다. 패키지 관리자는 pnpm 10.27.0입니다. `@hams-fam/sso-client`, Zustand, Google GenAI는 의존성에 있지만 현재 ERP 흐름에서 사용하지 않습니다.

```text
app/page.tsx          진입 페이지
  app/workspace.tsx     로그인·공통 레이아웃·모달·상태와 주기적 갱신
  components/workspace/ 메뉴별 화면 모듈·공통 카드와 표·표시 유틸리티
app/api/erp/route.ts  조회 API 및 action 기반 변경 API
lib/db.ts            DB 연결·테이블 초기화·샘플 구성원·한국 날짜
lib/password.ts      scrypt 해시 생성·검증·새 비밀번호 규칙
app/register/        회원등록 페이지
app/password-change.tsx 최초 필수 변경·일반 비밀번호 변경 모달
lib/types.ts         화면과 API의 데이터 타입
tests/erp.test.mjs    실제 로컬 서버 기반 통합 테스트
docs/                상세 분석과 운영 문서
```

## 검증

```powershell
pnpm exec tsc --noEmit
pnpm build
node --test tests/erp.test.mjs
```

통합 테스트는 별도 임시 DB와 로컬 프로덕션 서버를 사용합니다. 테스트가 실행하는 서버는 개발 서버 `3014`와 다른 무작위 포트를 사용합니다. `pnpm lint`는 별도 명령이며 테스트 통과가 린트·브라우저 검증까지 의미하지 않습니다.
