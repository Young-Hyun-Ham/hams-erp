# 현재 한계와 개선 검토

아래 항목은 [현재 코드](README.md)의 분석 결과이며 구현 완료 목록이 아니다. 문서화 작업에서는 서비스 동작을 변경하지 않는다.

## 기능 경계

| 영역 | 현재 범위 | 아직 없는 기능 |
| --- | --- | --- |
| 인증 | 회원등록·계정별 scrypt 해시·최초 변경·세션 무효화 | SSO·이메일 확인·초대·가입 승인·분실 재설정 |
| 인사 | 기본 정보·유형·프로젝트 한 문자열·월 금액 | 퇴사·휴직·휴가·계약 기간·복수 계약·조직 계층 |
| 근태 | 하루 한 출근·한 퇴근, 사무실·원격 | 당일 재출근·장소 변경·정정 승인·휴게·연장근로 계산 |
| 원격 | 앱 연결과 앱 내 활동 표시 | 화면·카메라·다른 앱 감시·업무 수행 증명·시계열 이력 |
| 급여 | 기본금액+수당-공제의 월 초안 | 세금·보험·일할·시급·실제 송금·승인 잠금·명세서 발행 |

## 데이터 정확성과 조회 규모

- 근태는 관리자 전체 또는 개인 범위의 최근 500건만 반환한다. 오래된 월 조회·CSV·오늘 인원이 전체 DB를 정확히 대표하지 못할 수 있다. 서버 월 필터·집계·페이지 처리가 개선 후보이다.
- GET의 4개 테이블 조회는 읽기 트랜잭션으로 묶지 않아 동시 변경 중 완전히 같은 시점을 보장하지 않는다.
- 미퇴근 차단은 선조회이며 다른 날짜를 포함한 단일 미퇴근 제약은 DB에 없다. 날짜 경계의 동시 요청까지 보장하려면 추가 검토가 필요하다.
- 서버의 출근일과 UI의 오늘은 각각 서버·클라이언트 시각에 의존한다. 원격 상태도 관리자 PC의 시계에 따라 달라질 수 있다.
- 원격 상태는 계정 PK 1개다. 다중 기기·탭의 마지막 보고가 우선하고, 통신 중단은 자동 종료되지 않는다. 기기 감지는 지원 브라우저·보안 컨텍스트·권한이 필요하며 미지원·거절 시 자동 판정 불가다. 절전·탭 중단으로 전달이 지연될 수 있고 활동 여부는 실제 업무 수행을 입증하지 않는다.
- 원격 시작 후 heartbeat는 출근 조건을 다시 검사하지 않는다. 날짜 변경·세션 만료는 자동 퇴근·종료가 아니다.
- 정산 base는 생성 당시 현재 salary이며 과거 급여·계약 버전을 복원하지 않는다. 근태는 급여 산식에 쓰이지 않는다.

## 무결성과 감사

DDL에는 참조 FK·상태 CHECK가 없다. 인증 컬럼 추가·해시 보완 전환은 있지만 전체 버전별 마이그레이션 프레임워크는 없다. 구성원 수정은 영향 행 수를 검사하지 않아 없는 ID에도 성공할 수 있다. 중복 이메일 선조회와 쓰기는 단일 트랜잭션이 아니므로 관리자 등록의 동시 충돌은 일반 DB 오류가 될 수 있다. 공개 회원등록은 DB 유일 제약 충돌도 409로 처리한다.

퇴근·로그아웃은 관련 UPDATE를 batch로 묶지만 모든 사전 검증까지 한 트랜잭션으로 처리하지 않는다. 급여 검토 완료도 수정 잠금이 아니다. 누가 언제 값을 바꿨는지 감사 로그, 원격 동의 정책 버전·동의 시각, 기록 보존·삭제 자동화는 없다.

시드는 API 초기화와 결합되어 새 서버 인스턴스에서도 재시도된다. 운영 스키마 변경·샘플 데이터와 실사용 데이터 분리에는 별도 마이그레이션·프로비저닝 설계가 필요하다.

## 인증과 배포

DB 회원등록은 이메일 소유 확인·가입 승인 없이 가능하다. 초기 비밀번호는 요청에 따라 공통값이며 최초 변경을 강제하지만, 최초 변경 전 본인 확인·초대 토큰·재설정 절차는 아직 없다. 사내 접근 대상 관리와 실제 사용자 확인을 연결하는 작업은 별도다. 설치된 SSO 패키지는 아직 사용하지 않는다.

비밀번호는 계정별 salt·scrypt 해시로 저장한다. 로그인 제한은 이메일별이고 성공 시 초기화한다. 회원등록·비밀번호 변경의 별도 속도 제한은 없다. 세션은 8시간 고정이며 비밀번호 변경 시 전체 세션 삭제·재발급을 하지만 주기적 자동 연장·회전·만료 행 정리는 없다. Origin 검사는 헤더 존재 시 Host만 비교하고 별도 CSRF 토큰은 없다.

쿠키 Secure는 VERCEL=1 또는 request.url의 HTTPS 판정으로 켠다. 다른 프록시 배포에서도 실제 Set-Cookie를 확인한다. 배포 환경 변수·원격 DB 오류는 코드 분석만으로 실제 설정 여부를 단정할 수 없다.

현재 `data/erp.db`는 추적 중이다. 인사·근태·급여 데이터가 포함될 수 있으므로 실사용 기록 보관·백업·저장소 추적 정책을 별도 관리해야 한다. 이 문서는 해당 DB 내용을 열람하지 않았다.

## UI와 운영 확장

한 클라이언트 컴포넌트에 로그인·5개 화면·요청·타이머·CSV가 모여 있다. 기능 확대 시 도메인별 컴포넌트·hook·서버 검증 모듈로 분리할 수 있다. 탭·필터 URL 보존, 로딩·세션 만료 알림의 일관성, 모달 포커스 이동·키보드 접근은 추가 검증 대상이다.

15초 전체 폴링은 구성원·근태·정산까지 함께 조회한다. 이용자 증가 시 조회 범위·주기·상태 전송 모델을 조정할 수 있다. WebSocket·SSE·백그라운드 데몬·데스크톱 에이전트는 현재 없다.

## 개선 순서 제안

1. 현재 기능 검증: 배포 환경 변수·로그인·원격 선행 조건·개인 권한을 실제 환경에서 확인한다.
2. 운영 기반: 실사용 인증·DB 마이그레이션·샘플 분리·감사·보관 정책을 설계한다.
3. 회사 규칙: 근태 정정·근무 형태 변경·급여 산식·계약 모델을 구체화한다.
4. 규모와 신뢰성: 서버 집계·페이지 처리·동시성·다중 기기·시각 판정을 보강한다.

이는 후속 검토 제안이며 이번 문서화에 기능 변경을 포함하지 않는다.
