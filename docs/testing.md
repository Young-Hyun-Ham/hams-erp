# 테스트와 확인 절차

근거: [tests/erp.test.mjs](../tests/erp.test.mjs). 회원등록·계정별 비밀번호 변경에 맞춰 테스트를 확장했다.

## 자동 검증 명령

프로젝트 디렉터리에서 실행한다. 테스트는 기존 프로덕션 빌드가 필요하므로 코드 변경 후 먼저 빌드한다.

```powershell
pnpm exec tsc --noEmit
pnpm build
node --test tests/erp.test.mjs
node --test tests/remote-state.test.mjs
```

별도 `test` package script는 없다. `pnpm lint`는 선택적 별도 린트 명령이다. TypeScript·빌드·API 테스트·린트·브라우저 검증은 서로 다른 검증 범위다.

## 통합 테스트가 하는 일

ERP 테스트 부모 1개 안에서 12개 세부 시나리오를 순서대로 실행한다. 부모까지 포함하면 13개다. remote-state 테스트는 최소화·잠금·미지원·기존 데이터·3분 경계·종료 우선순위의 5개 판정 시나리오를 검증한다.

1. UUID가 포함된 `data/test-<uuid>.db` 경로를 만든다.
2. 32000~41999 범위 무작위 포트로 `next start --hostname 127.0.0.1`을 자식 프로세스에서 실행한다.
3. 이전 버전 employees·sessions 스키마와 기존 구성원 1명·세션을 생성해 자동 인증 전환을 검증한다. 프로세스 환경 변수로 별도 DB를 지정한다.
4. 준비될 때까지 루트 HTTP 응답을 최대 약 20초 기다린다.
5. 실제 GET·POST API 요청과 직접 관리한 쿠키로 검증한다.
6. 같은 DB로 서버를 재시작하고 변경된 비밀번호·인사·근태·정산의 지속성과 이전 인증 환경 변수 무시를 확인한다.
7. finally에서 서버를 종료하고 해당 DB·wal·shm 파일만 삭제한다.

전체 테스트 제한은 90초다. 무작위 포트 충돌·자식 프로세스 권한 제한·Windows 파일 잠금은 실행 환경 문제로 발생할 수 있다. 파일 정리에 실패하면 잔여 테스트 DB가 남을 수 있으므로 경로와 종료 상태를 확인한다. 기존 업무 DB를 지워 해결하지 않는다.

## 자동 시나리오의 실제 범위

| 세부 시나리오 | 확인 내용 |
| --- | --- |
| 인증과 출처 | 기존 DB 전환·인사 보존·salt별 해시, 초기 접근 제한, 현재·확인·새 값 검증, 비밀번호 변경·기존 세션 폐기, 해시 응답 제외, 개인 범위 |
| 회원등록 | 페이지 응답, 필드 검증·이메일 중복, 관리자 권한 주입 무시, 초기 로그인·필수 변경, member 권한 |
| 회원정보 변경 | 로그인·최초 변경 제한, 이름·소속·직무 검증·trim, 본인만 변경, 다른 계정 ID·권한·급여·이메일 주입 무시 |
| 비밀번호 재변경 | 최초 변경 이후 현재 값·확인 검증, 새 세션 사용, 이전 비밀번호 로그인 거절, 기존 세션 전부 무효화 |
| 인사 | member 수정 거절, 잘못된 날짜 거절, 신규·중복 이메일·프로젝트 수정 |
| 원격 시작 | 출근 전 거절, 동시 원격 출근의 한 건 저장, 동의 확인, 업무·visible 저장, 다른 사용자 범위 제외 |
| 기기 활동 | 기존 remote 행의 마이그레이션·보존, active/idle/locked/unknown 저장, 잘못된 상태 거절, 본인 범위, 구버전 active 보고가 활동 중으로 취급되지 않음 |
| 원격지원설정 | 기본 5분, 관리자·최초 변경 제한, 1~120분 정수 검증, 구성원 공통 조회, 재시작 후 설정 유지 |
| 퇴근 | 출근·원격 종료 저장, 반복 퇴근·당일 재출근 거절, 종료 후 heartbeat가 공유를 재개하지 않음 |
| 정산 | 관리자 권한, 월 형식, 초안 생성, 과다 공제 거절, 수당·검토 저장, 재생성 유지, 개인 조회 |
| 재시작 | 구성원·퇴근·정산·변경 비밀번호 유지, 이전 인증 환경 변수와 무관한 로그인, 관리자 생성 계정 최초 변경 표시 |
| 로그아웃 | 현재 세션 무효화, 관리자 세션 유지 |

과거 ERP_ENABLE_DEMO_LOGIN 값을 false로 두어도 DB 계정별 비밀번호 로그인이 가능한지 확인한다. 테스트가 가짜 DB가 아닌 로컬 SQLite를 쓰더라도 원격 Turso 통신이나 Vercel 배포를 검증하는 것은 아니다. 해시 검사에는 별도 자식 프로세스를 사용해 Windows에서 DB 파일 핸들이 남지 않게 한다.

## 수동 원격근무 테스트

### 준비

개발 서버는 http://localhost:3014 를 사용한다. Vercel에서는 새 배포 URL을 사용한다. 일반 창과 시크릿 창 또는 서로 다른 브라우저 프로필로 관리자와 근무자의 쿠키를 분리한다. 같은 일반 브라우저의 두 탭만으로는 계정이 분리되지 않는다.

관리자는 `admin@hams.demo`, 근무자는 `member@hams.demo` 또는 `partner@hams.demo`를 사용한다. 최초에는 hams1234!로 로그인하고 필수 변경을 완료한다. 이후에는 각자 변경한 비밀번호를 사용한다. 근무자는 오늘 아직 출근하지 않은 계정이어야 한다.

회원등록 수동 확인: 로그인 화면의 회원등록 → 새 이메일로 등록 → 초기 비밀번호 로그인 → Escape·배경 클릭으로 변경 모달을 닫을 수 없는지 확인 → 새 비밀번호·확인 입력 → 업무 화면 진입 → 로그아웃 후 변경한 비밀번호로 재로그인한다. 변경 전 API 제한과 해시 저장은 자동 테스트로 별도 확인한다.

### 정상 흐름

1. 근무자 창에서 출퇴근 관리 → 원격 근무 선택 → 출근하기.
2. 원격근무 → 내 업무 상태 공유 → 업무 입력 → 동의 → 공유 시작.
3. 관리자 창의 원격근무 화면에서 약 15초 내 목록 반영 확인.
4. 활동 감지 권한을 허용하고 기기에서 작업 후 활동 상태 확인.
5. 공유 종료 시 관리자 목록에서 제외되지만 출퇴근 기록은 근무 중인 점 확인.
6. 다시 공유를 시작하고 퇴근 시 출근 마감과 공유 종료를 함께 확인.

### 상태 변화

| 조작 | 예상 관찰 |
| --- | --- |
| 브라우저 최소화 후 다른 프로그램에서 입력 | 활동 중 유지, 최소화만으로 자리비움이 되지 않음 |
| 기기 전체에서 설정 시간 동안 입력 없음 | IdleDetector idle 보고 후 자리 비움 |
| 화면 잠금·잠금 해제 | locked 보고 후 자리 비움, active+unlocked 보고 후 활동 중 |
| 권한 거절·미지원 환경 | 자동 판정 불가, 업무와 연결 공유는 계속 |
| 공유 중 권한 해제·재허용 | unknown 보고, 기기 활동 감지 허용 버튼으로 재시도 |
| 앱 종료·네트워크 차단 | 마지막 heartbeat에서 3분 초과 후 연결 확인 필요, 카드 유지 |
| 명시적 공유 종료·퇴근·로그아웃 | ended_at 반영 후 카드 제외 |
| 공유 중 새로고침 | 미종료 공유 상태 복구와 heartbeat 재개 가능 |
| 관리자 사용자 메뉴 → 원격지원설정 → 시간 변경 | 다음 15초 데이터 갱신 후 각 공유 브라우저가 감지기를 새 시간으로 재시작 |

지원 브라우저의 HTTPS 또는 localhost에서 확인한다. 개발자 도구 Sensors의 Idle Detector 에뮬레이션으로 active/idle 및 locked/unlocked도 확인할 수 있다. 상태 전환은 브라우저 타이머·네트워크·관리자 조회 지연을 고려한다. 기기 무활동 테스트 중 다른 프로그램에서 입력해도 무활동이 해제될 수 있다. 한 계정의 다중 탭은 상태가 섞이므로 피한다. 탭 중단·절전은 통신이 멈출 수 있다.

### 선행 조건 오류 재현

출근 전 또는 사무실 출근 계정에서 공유 시작하면 400과 `원격 출근 후 상태 공유를 시작해 주세요.`가 나와야 한다. 이미 사무실 출근·퇴근한 계정은 당일 장소 변경·재출근이 안 되므로 다른 미출근 샘플 계정을 사용한다. 운영 DB의 기록을 지워 테스트를 초기화하지 않는다.

## 아직 별도로 필요한 검증

실제 OS 입력·최소화·잠금·권한 허용/철회·새로고침 시 감지 재개·백그라운드 제한은 위 수동 절차로 별도 검증한다. 브라우저 렌더링·모바일 레이아웃·모달 키보드 접근·CSV 다운로드, 프로덕션 쿠키·도메인·프록시 헤더, 로그인 실패 제한 동시성, 세션 만료·자정 경계·원격 DB 장애도 자동 시나리오만으로 검증되지 않는다.
